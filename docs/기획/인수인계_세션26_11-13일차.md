## 2. 11일차에 고친 것 (커밋 완료)

### 2.1 발의한 매각 지시가 목록에 없어 체결이 불가능했다 [CRITICAL]

`fx_trade_history.trade_date` 는 **희망 집행일(미래)** 인데 외화매도이력 기본 필터가
`기간 종료 = 오늘` 이라 방금 만든 지시가 100% 탈락했다.

- **이행 대기 고정 패널** — 조회 필터와 무관하게 미완료(발의/승인/부분체결) 전량 표시.
  `FxOrdersTab` 의 `pendingOrders` prop 은 페이지의 A패턴 훅에서 온다.
  **금지**: 이 패널을 탭 자체 조회 결과(`hist.data`)로 대체하지 말 것.
- 기본 기간 종료 `addBizDays(today, 10)`, 필터 라벨 `발의일 시작/종료`,
  표 첫 컬럼 `매도발의일(집행일)` — 실제 체결일은 행을 펼쳐야 나온다.
- 딥링크 `?tab=orders&currency=X&order={id}` → 해당 카드 강조 + 체결 모달 자동 오픈.

### 2.2 실무 담당자에게 매도 발의 경로가 없었다 [CRITICAL]

초과분 발의 UI 가 권한 제한 메뉴(자금정책)에만 있었다.
`src/lib/fxBandExceed.ts` 로 산출·payload 를 SSOT 화하고 **세 곳**에 연결:
FX 리짐 전략 상단 / 외화거래명세 › 외화매도이력 상단 / **대시보드 이슈 티커**(`fx_band_{법인}`).

⚠ 상한은 **의결된 정책 밴드(`fx_target_max`)** 다. σ×Z 실효한도는 밴드를 만드는 계산기일 뿐이니
실무 화면에 복제하지 말 것(세션19차 6.2%/27.9% 사고와 같은 구조).

### 2.3 회의체가 정한 총량을 지시로 등록할 수 없었다

`FxOrderProposeModal` — **지시일 소급 가능**한 직접 등록. 승인은 `window.confirm` 대신
화면 안 패널로, `승인만` / `승인 후 체결 등록` 두 갈래.

### 2.4 원장을 재고 명세형으로 전환

같은 처분이 로트 행(생애 누적)과 유출 행에 **두 번** 나오던 것 + 자금일보·수동 유출이
`fx_trade_fills` 가 없어 **원장에서 통째로 누락**되던 것을 함께 해소.
로트 1건 = 1행, 처분금액 클릭 → 처분 내역 펼침(`consumptionsByLotId` 사용).

**금지**: 원장에 날짜순 유출 행을 다시 섞지 말 것. 원장 = 재고, 외화매도이력 = 거래.

## 3. 12일차에 만든 것 (커밋 완료)

### 3.1 계좌 간 대체 — `docs/db/fx_lot_transfer.sql` (실행 완료)

⭐ **대체 = 원자적 [FIFO 소진 + 신규 로트 생성] 쌍.** 총 외화 잔액은 변하지 않는다.
**금지**: 유출 등록 + 유입 등록 두 번으로 처리하지 말 것 — 잔액이 잠깐 어긋나고 손익이 두 번 잡힌다.

평가 방식은 **법인별 정책** `policy_params.fx_transfer_valuation`:

| | `carryover` (기본) | `revalue` |
|---|---|---|
| 신규 로트 | 소진 로트마다 1:1 | 1건 |
| 장부환율·취득일 | 원본 승계 → FIFO 순서 보존 | 대체환율 / 대체일 |
| 실현손익 | 0 | (대체환율 − 장부환율) × 금액 |

⚠ 각 대체 건에 `valuation_method` 를 기록한다 — 정책이 바뀌어도 과거 이력 해석이 흔들리면 안 된다.
⚠ `fx_lots` 의 `unique(company,currency,source_type,source_id)` 때문에 원가승계로 여러 로트를
만들 때 `source_id` 에 대체 id 를 넣으면 충돌 → 링크는 **`transfer_id` 컬럼**, `source_id` 는 NULL.

UI: 외화거래명세 › 데이터 등록 › `🔄 계좌 간 대체`(`FxTransferCard`). 저장 전 원가승계 미리보기.
정기예금 중도해지는 체크박스로 명시 허용.

### 3.2 거래 유형 — `docs/db/fx_txn_type.sql` (⚠ 미실행)

`source_type`(어디서 만들었나)과 `txn_type`(무슨 거래인가)을 분리.
매입대금 결제가 매각과 똑같이 기록돼 **환차손익 요약의 매각 실적이 부풀려지던** 문제.

- 유출: `sale`(환전) / `payment`(대외 지급) / `transfer`(내부 대체)
- 유입: `opening` / `acquisition` / `interest` / `transfer`
- backfill: `fx_trade_history`→`sale`, `transfer`→`transfer`, 나머지 유출→`payment`
- `consume_fx_lots_for_source` 에 `p_txn_type` 인자 추가.
  ⚠ 인자 추가는 오버로드를 만들므로 **구 8인자 버전을 drop 후 재생성**한다(SQL 안에 포함).
- SSOT: `src/lib/fxTxnType.ts` (`summarizeRealizedPnl` 포함)
- UI: 유출 등록 폼에 거래 유형 선택 / 환차손익 요약에 유형별 3줄 / 원장 처분 내역에 유형 배지

### 3.3 정기예금 해지·재예치 — `docs/db/fx_term_deposit_settle.sql` (⚠ 미실행)

해지 = **[원금 대체 + 이자 신규 로트] 한 트랜잭션**(`settle_fx_term_deposit`).
원금은 `transfer_fx_lots` 재사용이라 평가 방식도 법인 정책을 따른다.
⚠ **이자는 새로 생긴 외화**라 원가승계가 아니라 **해지일 환율의 신규 로트**여야 한다 —
원금 장부환율로 넣으면 원가가 희석된다.
재예치 = `to_account_type='term_deposit'` 대체. 중도해지는 `p_allow_early`.
`link_fx_lots_to_investment` 로 기존 건 1회 수동 매핑.
UI `FxTermDepositCard` — 목록·만기 강조·정합성 점검·매핑.
⚠ `investments` 만기처리는 여기서 하지 않는다(별도 도메인, 안내만).

### 3.4 원장 정렬·필터

## 3-A. 13일차 — 권한 UI 를 사이드바와 동일한 트리로

### 문제: UI 가 아니라 **두 목록이 실제로 어긋나 있었다**

사이드바 메뉴(`NAV_GROUPS`)는 `Sidebar.tsx` 안에, 권한 목록(`MENU_SLUGS`)은 `UsersPage.tsx`
안에 **따로** 정의돼 있었다(§1-A 4번 위반). 실제 드리프트:

| | 내용 |
|---|---|
| ① | **`audit-log`(변경 이력 로그)가 권한 목록·역할 기본값 양쪽에 없었다** → master 외에는 아무도 볼 수 없고 **부여할 방법 자체가 없던 상태** |
| ② | 라벨 5건 불일치 — 특히 `환율 국면`은 7일차에 `FX 리짐 전략`으로 개명했는데 권한 화면만 옛 이름 |
| ③ | `daily`/`history` slug 를 화면 2개씩 공유하는데 한 줄로만 보여, 체크 하나가 화면 둘을 여는 걸 알 수 없었다 |

### 해결

- **`src/lib/navTree.ts` SSOT** — Sidebar 와 UsersPage 가 같은 상수를 읽는다.
  메뉴를 추가·개명하면 권한 화면이 자동으로 따라온다.
  **금지**: 메뉴 목록을 화면 안에 다시 정의하지 말 것.
- **`MenuPermissionTree`** — 사이드바와 동일한 아이콘·라벨·순서. 섹션 3-state 체크,
  slug 병기, 같은 slug 는 묶어 `함께 열림` 표시, **역할 기본값 미리보기**(커스텀을 안 켜도
  실제 무엇이 열리는지 보인다).
- **3탭 → 단일 트리**. 작업 권한(`action_permissions`)을 각 메뉴 행에 인라인으로 붙였다.
  ⚠ menu slug 와 `SectionKey` 는 1:1 이 아니다:
    · `history`/`issue_history` — slug 는 공유, 작업 권한은 따로 → **작업 권한은 항목 단위**
    · `daily_write`/`daily_submit` — 한 화면에서 갈림 → `extraSections` 하위 행
    · 조회 전용 화면(대시보드·환율 현황·리짐·감사로그)은 `section` 없음 → "조회 전용" 표시
  카테고리 권한(`allowed_categories`)은 **메뉴가 아니라 자금일보 안의 입출금 항목 종류**라
  트리로 대체 불가 → 자금일보 작성 행 아래 접이식으로 이동.
- 모순 조합 방지: 조회를 끄면 입력·삭제도 꺼지고, 입력·삭제를 켜면 조회가 켜진다.
  메뉴 접근이 없으면 작업 권한 체크는 비활성.
- **관리 섹션은 `masterOnly`** — 표시만 하고 체크박스 없음.
  ⚠ `admin` 은 "업무 관리자"이지 시스템 관리자가 아니다. **실질 관리자는 master**
  (2026-08-20 사용자 확인) — 관리 메뉴의 master 하드코딩은 결함이 아니라 설계다.
- `audit-log` 는 부여 가능해졌지만 **역할 기본값에는 넣지 않았다**(`fx-regime` 과 동일 opt-in).

⚠ `treasury_users.menus`·`action_permissions`·`allowed_categories` 스키마와 `hasMenu()`/
`canAction()`/`hasCategory()` 로직·slug 값은 **그대로**다 — DB 마이그레이션 불필요,
기존 사용자 권한 유지.

- 필요한 계정에 `audit-log`(변경 이력 로그) 권한 부여 — 이번에 처음 부여 가능해졌다.
- `daily`/`history` slug 분리(`daily-report`/`daily-report-list` 등) — 지금은 "함께 열림"으로
  표시만 한다. 분리하려면 기존 `treasury_users.menus` 배열 마이그레이션이 필요하다.

### 4.4 이후 후보

- 이자 수취를 정기예금 해지 외 경로(중간 이자 지급)에서도 등록할 수 있게
- `txn_type` 사후 수정 UI — backfill 로 `payment` 가 된 과거 유출 중 실제로는 환전이었던 건

## 5. 이 영역에서 반복된 함정 (재발 방지)

| 함정 | 규칙 |
|---|---|
| 날짜 컬럼의 의미를 확인 안 함 | `trade_date`=발의일, `fill_date`=체결일, `due_date`=이행기한. **미완료 항목은 조회 필터와 무관하게 보여라** |
| 같은 지표를 화면에서 재계산 | 외화비중은 `usePolicyDashboard`, 리짐은 `useFxRegime`, 밴드 초과는 `lib/fxBandExceed` |
| 서버·클라이언트 정렬 규칙 분리 | `fx_fifo_account_rank()` ↔ `parseAccountPriority()` 는 **같은 규칙**이어야 미리보기와 실제가 일치 |
| `window.confirm` 사용 | 크롬이 반복 대화상자를 차단하면 즉시 false 반환 → "눌러도 아무 일 없음". **화면 안 확인 패널**을 쓸 것 |
| 조건부 UI 가 사라지며 진행 중 작업 소실 | "지금 필요한가"와 "이미 진행 중인가"는 **다른 질문**. 둘 다 렌더 조건에 넣을 것 |
| 메뉴만 바꾸고 권한 화면을 잊음 | 메뉴 정의는 `src/lib/navTree.ts` **하나**다. 사이드바와 사용자 관리 권한 트리가 같은 상수를 읽는다 — 화면 안에 목록을 다시 정의하면 즉시 어긋난다. 새 메뉴는 `MENU_DEFAULTS` 도 함께 볼 것(안 넣으면 아무도 못 본다) |
| 프로덕션 DB 직접 조작 | SELECT 만 허용. DELETE/UPDATE/INSERT 는 사용자 승인 없이 절대 금지(CLAUDE.md §10) |
