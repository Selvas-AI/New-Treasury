# 외화 원장(FX Lot Ledger) 구축 기획안 — FIFO / 가중평균 환차손익

> 작성: 2026-08-05 (세션21차) · 상태: **기획 보고 · 구현 미착수**
> 요청: 외화 입출금 장부를 별도 구축하고, FIFO/가중평균 원가법에 따라 환차손익을 자동 계산.
> 사용자가 두 번 일하지 않도록 **원타임 입력 → 관련 장부 동시 반영** 플로우 구성.

---

## 1. 문제 정의

현재 회사는 외화 출금 시 **FIFO(선입선출)** 로 처리한다. 즉 환차손익은
"장부상 평균환율"이 아니라 **해당 금액이 실제 입금된 시점의 환율**과 매각·집행 환율의
차액으로 계산해야 한다. 회사에 따라 **가중평균법**을 쓰기도 하므로 두 방식을 모두 지원해야 한다.

**그런데 현재 시스템은 이 계산을 할 수 있는 데이터 자체가 없다.**

---

## 2. 현재 상태 진단 (조사 결과)

### 2.1 ⚠ 로트(취득 단위) 개념이 전혀 없음
전 코드베이스에 lot/tranche/FIFO/가중평균 구현이 **하나도 없다.** 외화는 전부 **잔액 스냅샷**으로만 관리된다.

| 항목 | 현재 | 문제 |
|---|---|---|
| `daily.fx_usd/eur/jpy/gbp/cny` | **잔액**(거래 아님). `InputPage`에서 사용자가 그날 잔액을 직접 입력 | "언제 얼마가 어느 환율로 들어왔는지" 정보 없음 |
| `daily.fx_krw` | 저장 시점 **시장환율 × 잔액** 을 곱해 저장 (`InputPage.tsx:64-78`) | **환율 자체는 저장 안 됨.** 곱한 결과만 남음 |
| `daily_report_items.amount_krw` | 항목 저장 시점 시장환율로 환산 후 저장 | 취득원가가 아니라 그 시점 시가 |
| `daily_reports.fx_rates` (jsonb) | DDL·타입에는 있으나 **쓰는 코드가 0개 — 죽은 컬럼** | 환율 스냅샷 보관 자리가 비어 있음 |

### 2.2 ⚠ `acq_rate`(장부환율)가 손으로 치는 값
`fx_trade_history.acq_rate` 는 주석상 "가중평균 취득환율"이지만 실제로는
**빈 칸에서 시작하는 자유 입력 텍스트**다 (`FxPolicyTab.tsx:1465-1472`, `FxPage.tsx:131`).
어떤 잔액·이전 거래와도 연결돼 있지 않고 검증도 없다.

→ 확정 환차손익 `completed_pnl = (completed_rate − acq_rate) × amount_fx`
(`useFxTradeHistory.ts:172-176`)는 **`acq_rate`가 null이면 조용히 0** 이 된다.
**이것이 사용자가 지적한 문제의 정확한 코드상 위치다.**

### 2.3 ⚠ 매매 이력과 잔액이 완전히 분리
`fx_trade_history` 의 매각 완료는 **`daily.fx_*` 를 전혀 건드리지 않고**
`daily_report_items` 도 만들지 않는다. 두 장부가 서로 모른다.

### 2.4 미실현 환차손익은 어디에도 없음
보유 외화의 평가손익을 계산·표시하는 코드가 없다. `fx_krw`가 조용히 흡수할 뿐이다.
(지분·국채는 `invest_eval_in/out` 으로 평가손익을 자동 기재하는데 외화만 없음)

### 2.5 결론: **소급 구축 불가 → 개시 로트로 시작해야 함**
- **수량(외화 금액)은 복원 가능**: 일자별 `daily.fx_*` 차분 + 일보 항목
- **환율은 복원 불가**: 어디에도 저장되지 않음. 유일하게 유추 가능한 건
  `daily.fx_krw ÷ Σ(통화별 잔액)` 인데 이건 **5개 통화 전체를 뭉갠 혼합 환율**이라 통화별 원가로 쓸 수 없음
- → **특정 시점을 개시일로 잡고 통화별 개시 로트를 수기 등록**하는 것이 유일하게 정직한 출발점

## 3. 핵심 설계 결정

### 3.1 로트는 항상 저장, 원가법은 "소진 시 원가환율 결정 규칙"으로만 작동
두 방식이 데이터 모델을 공유하게 만든다.

| 원가법 | 소진 시 적용 원가환율 | 로트 처리 |
|---|---|---|
| **FIFO** | 가장 오래된 로트의 `acq_rate` | 오래된 로트부터 차감, 로트별 정체성 유지 |
| **가중평균(WAVG)** | 해당 통화 잔여 로트의 가중평균환율 | 동일하게 차감하되 원가는 평균값 사용 |

→ 방식을 바꿔도 데이터 구조는 그대로. **각 소진 기록에 "적용된 방식"을 함께 저장**해
과거 기록이 나중에 재해석되지 않게 한다(원가법 변경은 **소급 적용하지 않고 이후 거래부터**).

### 3.2 ⚠ 환차손익을 자금일보 현금 라인으로 넣으면 **이중계상** — 넣지 말 것
가장 중요한 회계 판단이다.

USD 1,000을 @1,300에 취득해 @1,400에 매각한 경우:
```
USD 잔액  −1,000  (원화환산 −1,400,000)
KRW 잔액  +1,400,000
검증식: 입금 1,400,000 − 출금 1,400,000 − 잔액증감 0 = 0 ✓
```
실현이익 +100,000원은 **이미 잔액 변동에 녹아 있다**
(받은 원화가 내준 외화의 장부가를 초과한 만큼이 곧 이익).
여기에 손익 라인을 또 넣으면 현금이 두 번 계산되고 `DailyReportPage.tsx:732-755` 검증식이 깨진다.

**따라서 환차손익은 "현금 이동"이 아니라 "장부가 재분류" — 원장에서 산출해 공시(disclosure)한다.**

단, 일보에서 눈에 보이길 원하면 → **`invest_eval_*` 와 동일하게 검증식에서 제외되는
비현금 카테고리**로 추가한다. 이 경우 반드시 2곳 모두에 제외 처리 필요:
- `DailyReportPage.tsx:738-739` (validation)
- `DailyReportPage.tsx:416-417` (`liveItemSums`)

### 3.3 `daily.fx_krw` 의 의미는 바꾸지 않는다 (시가 유지)
`fx_krw`를 취득원가(장부가)로 바꾸면 대시보드 가용자금·외화비중 등
**모든 기존 숫자의 의미가 한꺼번에 바뀐다.** 따라서:
- `daily.fx_krw` = **시가**(현행 유지) → 기존 SSOT 규칙(`treasuryCalc.ts:9-13`) 그대로
- **장부가(원가)** 는 원장이 새로 제공하는 별도 지표
- **미실현 환차손익 = 시가 − 장부가** ← 지금까지 아무도 이름 붙이지 않던 값

### 3.4 원장이 외화 잔액의 SSOT가 되고, `daily.fx_*` 는 자동 동기화 미러
로트 이동이 일어나면 `daily.fx_{통화} = Σ(잔여 로트)` 를 자동 반영한다.
→ 기존 모든 판독부(대시보드·정책·일보)는 **코드 변경 없이** 그대로 동작.

### 3.5 JPY 단위 주의
내부 환율 단위는 전 통화 1단위 기준(`useFx.ts` `FX_UNITS` 모두 1)이나
화면 표기는 ¥100 단위다. **로트 금액은 네이티브 1단위, 환율은 원/1단위로 저장**하고
표시 단계에서만 100배 처리한다.

## 4. 데이터 모델 (신규 테이블 2개 + 기존 재사용 1)

```sql
-- ① 외화 취득 로트
create table fx_lots (
  id               uuid primary key,
  company          text not null,
  currency         text not null,              -- USD/EUR/JPY/GBP/CNY
  acquired_date    date not null,              -- 취득일 (FIFO 정렬 기준)
  original_amount  numeric not null,           -- 취득 원금 (외화, 네이티브 1단위)
  remaining_amount numeric not null,           -- 잔여 (소진되면 0)
  acq_rate         numeric not null,           -- 취득환율 (원/외화 1단위)
  source_type      text,                       -- 'opening'|'daily_report_item'|'manual'
  source_id        uuid,                       -- 역참조 (일보 항목 등)
  memo             text,
  created_by       text,
  created_at       timestamptz default now()
);
create index on fx_lots (company, currency, acquired_date);

-- ② 로트 소진 (출금 1건이 여러 로트를 소진할 수 있으므로 명세 단위로 기록)
create table fx_lot_consumptions (
  id             uuid primary key,
  company        text not null,
  currency       text not null,
  lot_id         uuid references fx_lots(id),
  disposed_date  date not null,
  amount         numeric not null,   -- 이 로트에서 소진한 외화액
  acq_rate       numeric not null,   -- 적용된 원가환율 (FIFO=로트환율 / WAVG=당시 평균)
  disposal_rate  numeric not null,   -- 처분(매각·집행) 환율
  realized_pnl   numeric not null,   -- (disposal_rate − acq_rate) × amount
  method         text not null,      -- 'FIFO'|'WAVG' — 적용 시점 방식 고정 기록
  source_type    text, source_id uuid,
  memo           text, created_by text,
  created_at     timestamptz default now()
);
```

**③ 원가법 설정은 기존 `policy_params` 재사용** (신규 테이블 불필요)
`(company, param_key='fx_cost_method', param_text='FIFO'|'WAVG')`
→ 법인별로 다르게 설정 가능하고, 정책회의 의결사항으로도 관리 가능.

## 5. 원타임 입력 워크플로우 (핵심 요구사항)

### 5.1 기존 자산이 이미 쓰고 있는 "연동 팝업" 패턴을 그대로 확장
앱에는 이미 **한 번 입력 → 두 장부 반영** 패턴이 있다
(`InvestExecutePopup` 등 4종: 자산 레코드 생성 + 일보 항목 생성을 `linked_type`/`linked_id`로 묶음).
FX도 **같은 계약(`onSaved(amount, currency, memo, linkedType, linkedId)`)** 을 따르면
`ItemsSection.handleLinkedSaved` 는 **수정 없이 재사용**된다.

### 5.2 외화 입금 (취득)
```
자금일보 > 입금 항목 추가 > 통화를 외화로 선택
  → [취득환율] 필드 자동 노출 (기본값 = 당일 시장환율, 편집 가능)
  → 저장
      ① daily_report_items 생성        (일보 라인)
      ② fx_lots 로트 1건 생성           (원장)
      ③ daily.fx_{통화} 자동 증액        (잔액)
```
**사용자 입력 1회 → 장부 3개 반영.** 새로 요구하는 정보는 **취득환율 하나뿐**이며,
이건 파생 불가능한 사업적 사실이라 반드시 사람이 확인해야 하는 값이다.

### 5.3 외화 출금 (매각 / 자금집행)
```
자금일보 > 출금 항목 추가 > 통화를 외화로 선택
  → [처분환율] 입력 (기본값 = 당일 시장환율)
  → ★ 실시간 미리보기: 적용 원가법에 따라
       "어느 로트에서 얼마가 소진되고 환차손익이 얼마인지" 표시
         예) FIFO — 2026-03-11 로트 600 @1,310 / 2026-05-02 로트 400 @1,352
             실현손익 +52,800원
  → 저장
      ① daily_report_items 생성
      ② fx_lot_consumptions 명세 기록 + fx_lots.remaining 차감
      ③ daily.fx_{통화} 자동 감액
      ④ 환차손익 원장 확정 (현금 라인 아님 → 검증식 무영향)
```
매각(→원화)이든 자금집행(외화 직접 지급)이든 **동일 공식**
(`(처분환율 − 취득환율) × 액`)이므로 하나의 플로우로 처리된다.

### 5.4 기존 외화매매 워크플로우와 연결 — `acq_rate` 자동 산출
현재 매도 발의 시 손으로 치던 `acq_rate` 를 **원장에서 자동 계산**해 채운다.
```
FX 정책 > 매도 발의 → acq_rate 자동 = 원가법에 따른 현재 원가환율 (읽기전용 + 근거 표시)
                    → 승인 → 완료(체결환율 입력)
                        → 이때 로트 소진 + 확정 환차손익 자동 기록
```
→ 사용자가 지적한 "장부상 평균환율이 실제 환차손 계산 환율이 아니다" 문제가 여기서 해소된다.

### 5.5 미실현 평가손익 자동 기재 (선택)
지분·국채가 이미 쓰는 `@auto:` 자동기재 패턴을 그대로 차용:
`@auto:fx:{통화}` prefix, `invest_eval_in/out` 과 동일하게 **검증식 제외**.
⚠ 기존 지분 effect가 `@auto:bond:` 를 건너뛰듯 `@auto:fx:` 도 건너뛰도록
`DailyReportPage.tsx:529` 에 skip 추가 필요 (안 하면 지분 effect가 FX 행을 삭제함).

## 6. 메뉴별 구현 위치

| 메뉴 | 신규/변경 | 내용 |
|---|---|---|
| **이력관리 > 외화 원장** | **신규** (기존 `외화매매거래` 확장·개명 권장) | 탭1 **보유 로트**(통화별 로트 목록·가중평균환율·장부가 vs 시가·미실현손익) / 탭2 **입출금 이력**(로트 생성·소진 명세 + 건별 실현손익) / 탭3 **환차손익 요약**(기간별 실현·미실현). 상단에 **개시 로트 설정** 버튼 |
| **자금정책 > FX 정책** | 변경 | **원가법 설정(FIFO/가중평균)** 카드 추가. `policy_params` 사용. 변경 시 "이후 거래부터 적용" 경고 + 의결사항 연계 가능 |
| **자금일보 작성** | 변경 | 외화 입출금 시 환율 입력 + 로트 소진 미리보기 (단일 진입점). 신규 `FxLotPopup` |
| **운전자금(운전자금 입력)** | 변경 | FX 필드에 "외화원장 연동" 표시 + **원장 잔액 ≠ daily 잔액 시 불일치 경고**(조정 로트 생성 안내) |
| **통합 상황판 / FX 정책** | 표시만 추가 | 외화 장부가·미실현손익 지표 노출 |

## 7. 단계별 로드맵

| 단계 | 내용 | 산출 | 리스크 |
|---|---|---|---|
| **1. 기반** | 테이블 2개 + 원가법 설정 + `fx_lots.ts` 계산 엔진(FIFO/WAVG 순수함수) + 단위 테스트 | 마이그레이션 SQL, lib | 낮음 |
| **2. 개시** | 외화 원장 화면(읽기) + **개시 로트 등록 UI** | 법인별 개시 잔액·장부환율 확정 | 낮음 — 기존 동작 무영향 |
| **3. 연동** | 자금일보 FX 입출금 팝업 (로트 생성·소진 + 미리보기) | **원타임 입력 완성** | 중 — `daily` 동시 기록, 검증식 주의 |
| **4. 매매 연계** | `fx_trade_history` 완료 시 자동 로트 소진 + `acq_rate` 자동 산출 | 수기 입력 제거 | 중 |
| **5. 평가손익** | `@auto:fx:` 미실현 손익 자동 기재 + 리포트 | 공시 완성 | 중 — 자동기재 정리 로직 주의 |

**1~2단계는 기존 화면에 전혀 영향을 주지 않으므로 안전하게 먼저 배포 가능.**

## 8. 리스크 및 사전 확인 필요 사항

| 항목 | 내용 |
|---|---|
| **소급 불가** | 과거 환율이 저장돼 있지 않아 이전 거래의 원가는 복원 불가. **개시일 이전은 하나의 개시 로트로 뭉쳐서 시작**하는 것이 유일한 방법 |
| **개시 장부환율** | 통화별 개시 취득환율을 회계팀이 확정해 줘야 함 (현 장부상 평균환율 사용 권장) |
| **잔액 불일치** | `InputPage`에서 FX 잔액을 직접 수정하면 원장과 어긋남 → 불일치 감지 + **조정 로트** 경로 필요 |
| **환차손익 이중계상** | §3.2 — 현금 라인으로 넣지 말 것. 넣으려면 검증식 2곳 모두 제외 처리 |
| **원가법 변경** | 소급 적용 금지. 각 소진 기록에 적용 방식을 남겨 과거 기록 보존 |
| **반려/삭제 시 원복** | `useDailyReportItems.removeItem`(`:88-93`)은 현재 **연동 자산을 되돌리지 않는 기존 잠재 버그**가 있음. FX 로트는 반드시 원복 경로를 함께 구현(기존 invest/loan 팝업 버그도 같이 해소) |
| **JPY 단위** | 네이티브 1단위 저장 / ¥100 표시 분리 (§3.5) |

## 9. 확인 요청 사항

구현 착수 전 아래 결정이 필요합니다.

1. **개시일** — 언제부터 원장을 시작할지 (예: 2026-09-01 또는 회계연도 시작일)
2. **개시 장부환율** — 통화별 개시 취득환율 (현 장부 평균환율 값)
3. **원가법** — 전 법인 FIFO 통일 vs 법인별 설정 (메디아나만 다르게 등)
4. **환차손익 일보 표시 여부** — 원장에서만 볼지, 자금일보에도 비현금 라인으로 표시할지
5. **착수 범위** — 1~2단계(안전) 먼저 vs 3단계까지 한 번에
