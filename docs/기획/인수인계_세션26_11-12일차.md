## 2. 11일차에 고친 것 (커밋 완료)

### 2.1 발의한 매각 지시가 목록에 없어 체결이 불가능했다 [CRITICAL]

`fx_trade_history.trade_date` 는 **희망 집행일(미래)** 인데 외화매도이력 기본 필터가
`기간 종료 = 오늘` 이라 방금 만든 지시가 100% 탈락했다.

- **이행 대기 고정 패널** — 조회 필터와 무관하게 미완료(발의/승인/부분체결) 전량 표시.
  `FxOrdersTab` 의 `pendingOrders` prop 은 페이지의 A패턴 훅에서 온다.
  **금지**: 이 패널을 탭 자체 조회 결과(`hist.data`)로 대체하지 말 것.
- 기본 기간 종료 `addBizDays(today, 10)`, 필터 라벨 `발의일 시작/종료`,
  표 첫 컬럼 `매도발의일(집행일)` — 실제 체결일은 행을 펼쳐야 나온다.
- 딥링크 `?tab=orders&currency=X&order={id}` → 해당 카드 강조 + 체결 모달 자동 오픈.

### 2.2 실무 담당자에게 매도 발의 경로가 없었다 [CRITICAL]

초과분 발의 UI 가 권한 제한 메뉴(자금정책)에만 있었다.
`src/lib/fxBandExceed.ts` 로 산출·payload 를 SSOT 화하고 **세 곳**에 연결:
FX 리짐 전략 상단 / 외화거래명세 › 외화매도이력 상단 / **대시보드 이슈 티커**(`fx_band_{법인}`).

⚠ 상한은 **의결된 정책 밴드(`fx_target_max`)** 다. σ×Z 실효한도는 밴드를 만드는 계산기일 뿐이니
실무 화면에 복제하지 말 것(세션19차 6.2%/27.9% 사고와 같은 구조).

### 2.3 회의체가 정한 총량을 지시로 등록할 수 없었다

`FxOrderProposeModal` — **지시일 소급 가능**한 직접 등록. 승인은 `window.confirm` 대신
화면 안 패널로, `승인만` / `승인 후 체결 등록` 두 갈래.

### 2.4 원장을 재고 명세형으로 전환

같은 처분이 로트 행(생애 누적)과 유출 행에 **두 번** 나오던 것 + 자금일보·수동 유출이
`fx_trade_fills` 가 없어 **원장에서 통째로 누락**되던 것을 함께 해소.
로트 1건 = 1행, 처분금액 클릭 → 처분 내역 펼침(`consumptionsByLotId` 사용).

**금지**: 원장에 날짜순 유출 행을 다시 섞지 말 것. 원장 = 재고, 외화매도이력 = 거래.

## 3. 12일차에 만든 것 (미커밋)

### 3.1 계좌 간 대체 — `docs/db/fx_lot_transfer.sql` (실행 완료)

⭐ **대체 = 원자적 [FIFO 소진 + 신규 로트 생성] 쌍.** 총 외화 잔액은 변하지 않는다.
**금지**: 유출 등록 + 유입 등록 두 번으로 처리하지 말 것 — 잔액이 잠깐 어긋나고 손익이 두 번 잡힌다.

평가 방식은 **법인별 정책** `policy_params.fx_transfer_valuation`:

| | `carryover` (기본) | `revalue` |
|---|---|---|
| 신규 로트 | 소진 로트마다 1:1 | 1건 |
| 장부환율·취득일 | 원본 승계 → FIFO 순서 보존 | 대체환율 / 대체일 |
| 실현손익 | 0 | (대체환율 − 장부환율) × 금액 |

⚠ 각 대체 건에 `valuation_method` 를 기록한다 — 정책이 바뀌어도 과거 이력 해석이 흔들리면 안 된다.
⚠ `fx_lots` 의 `unique(company,currency,source_type,source_id)` 때문에 원가승계로 여러 로트를
만들 때 `source_id` 에 대체 id 를 넣으면 충돌 → 링크는 **`transfer_id` 컬럼**, `source_id` 는 NULL.

UI: 외화거래명세 › 데이터 등록 › `🔄 계좌 간 대체`(`FxTransferCard`). 저장 전 원가승계 미리보기.
정기예금 중도해지는 체크박스로 명시 허용.

### 3.2 거래 유형 — `docs/db/fx_txn_type.sql` (⚠ 미실행)

`source_type`(어디서 만들었나)과 `txn_type`(무슨 거래인가)을 분리.
매입대금 결제가 매각과 똑같이 기록돼 **환차손익 요약의 매각 실적이 부풀려지던** 문제.

- 유출: `sale`(환전) / `payment`(대외 지급) / `transfer`(내부 대체)
- 유입: `opening` / `acquisition` / `interest` / `transfer`
- backfill: `fx_trade_history`→`sale`, `transfer`→`transfer`, 나머지 유출→`payment`
- `consume_fx_lots_for_source` 에 `p_txn_type` 인자 추가.
  ⚠ 인자 추가는 오버로드를 만들므로 **구 8인자 버전을 drop 후 재생성**한다(SQL 안에 포함).
- SSOT: `src/lib/fxTxnType.ts` (`summarizeRealizedPnl` 포함)
- UI: 유출 등록 폼에 거래 유형 선택 / 환차손익 요약에 유형별 3줄 / 원장 처분 내역에 유형 배지

### 3.3 원장 정렬·필터

7개 컬럼 헤더 클릭 정렬(↕/▲/▼) + 상태 필터(잔존/소진 중/소진 완료) + 잔액 하한 + 건수 표시.

**해결하려는 실측 단절**: `investments` 의 외화 정기예금 3건과 원장 `term_deposit` 로트가

- 예치: 운용자금 신규 등록 → 원장 대체(보통예금/MMDA → 정기예금)를 `investment_id` 달아 실행
- 해지: `setActive(false)` 시 ① 원금 대체(정기예금 → 보통예금/MMDA) ② **이자는 해지일 환율의
  신규 로트**(`txn_type='interest'`) — 이자는 새로 생긴 외화라 원가승계 대상이 아니다
- 재예치: 정기예금 → 정기예금 대체(새 만기·금리, 원가는 승계)
- 정합성 점검 패널: 원장 term_deposit 합계 vs `investments` 외화 정기예금 active 합계

**착수 전 사용자 확인 필요** (설계 문서 §4 B·C·D):
- B: 해지 시 원금 행선지 — 매번 선택 제안

- D: 기존 정기예금 2건 매핑 — 1회 수동 매핑 UI 제안

`fx_lots.investment_id` 컬럼은 `fx_lot_transfer.sql` 에 **이미 들어가 있다**(추가 마이그레이션 불필요).
