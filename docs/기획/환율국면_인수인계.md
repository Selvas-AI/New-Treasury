## 4. ⚠️ 반드시 알아야 할 것 (모르면 같은 함정을 다시 밟는다)

### 4.1 ⛔ 프로덕션 DB 직접 조작 금지
Supabase 프로덕션에 **DELETE/UPDATE/INSERT 를 직접 실행하지 말 것.** 조회(SELECT)만 허용.
2026-06-25 에 실제로 데이터 106건이 소실된 사고가 있었다(`CLAUDE.md` §10 참조).
데이터 변경이 필요하면 **UI 버튼을 만들어 사용자가 클릭**하게 하거나 명시적 승인을 받는다.

### 4.2 데이터·API 제약 (전부 실측으로 확인됨)
| 제약 | 내용 | 대응 |
|---|---|---|
| **PostgREST `max-rows=1000`** | `limit: 4000` 을 줘도 1,000행에서 **조용히 잘림**. "데이터가 거기까지만 있다"고 오해하기 쉬움 | `useFxHistory` 에 keyset 페이지네이션 구현됨 |
| **ECOS 1회 500건 상한** | 여러 해를 한 번에 요청하면 뒷 구간이 조용히 잘림 | 백필·보충 모두 **연 단위**로 끊어 호출 |
| **GAS 연속 호출 간헐 실패** | `"사용할 수 없는 주소"` 예외. 같은 요청을 단독 실행하면 정상 → 연도 문제가 아니라 일시 거부 | 연도별 3회 재시도(8s→16s 백오프) + 연도 간 5초 간격. 한 해 실패해도 배치 중단 안 함 |
| **ECOS 는 종가만 제공** | 고가/저가 없음 → ADX·ATR 계산 불가 | ADX→**Efficiency Ratio**, ATR→**변동성 Z-Score** 로 대체 |
| GAS 응답 20~30초 | ECOS 자체 지연. 우리 코드 문제 아님 | `FXHISTORY_TIMEOUT_MS = 60000` |
| GAS 일일 할당량 | 2026-07-01 에 UrlFetch 할당량 소진으로 전 시세 장애 발생 전력 | **폴링 금지**. `isGasBlocked()` 서킷브레이커 준수 |

### 4.3 엔진 설계상 반드시 지킬 규칙
1. **평활가와 원시가를 용도별로 분리한다.**
   추세 지표(EMA·MACD·ER·순변동) = 칼만 평활가 / 변동성·볼린저 = **원시 종가**.
   평활가로 변동성을 재면 정의상 과소평가된다(실측 1.11% vs 실제 5.72%).
2. **`minTrendMovePct` 크기 게이트를 제거하지 말 것.**
   ER 은 스케일 불변이라, 환율이 0.1원 움직여도 단조롭기만 하면 ER=100 이 나온다.
   20영업일 랜덤워크 1σ ≈ 2% 이므로 1.5% 미만은 추세로 보지 않는다.
3. **칼만 q/r 는 가격 수준에 종속된 분산값이다.** 근거 문서의 `q=0.5,r=10` 은 원/달러에서 약 4영업일 지연을 만든다. 현재 `q=2,r=10`(약 1.8일).
4. **백테스트는 반드시 `evaluateRegime()` 을 그대로 호출한다.** 백테스트 전용 판정 로직을 만들면 실전과 어긋나 아무도 결과를 믿지 않게 된다.
5. **look-ahead 금지.** 항상 `series.slice(0, i+1)` 만 넘긴다.
6. **`volZScore` 는 누적합(prefix sum) 구현을 유지할 것.** 슬라이스 방식은 O(n²)이라 백테스트에서 브라우저가 멈춘다.

### 4.4 React / 환경 함정
- **훅 반환 객체·콜백은 반드시 `useMemo`/`useCallback` 메모이즈.** 과거 무한 렌더 루프로 페이지가 얼어붙은 전례 있음.
- **JSX 헬퍼 컴포넌트를 렌더 함수 안에 정의하지 말 것.** 매 렌더 remount 되어 입력 포커스가 유실된다.
- **`<Routes>` 자식에 조건부를 걸 때는 라우트마다 개별로.**
- ⚠ **미리보기 환경 특성**: 브라우저에서 `/fx-regime` 로 **하드 로드하면 `/dashboard` 로 리다이렉트된다.**
  이건 이 기능의 버그가 아니다 — 기존 `/policy` 등 모든 라우트가 동일하다(프리뷰 SPA 폴백 문제).
  검증할 때는 SPA 내부 이동을 쓸 것:
  ```js
  history.pushState({}, '', '/fx-regime/메디아나');
  window.dispatchEvent(new PopStateEvent('popstate', { state: {} }));
  ```
- 로그인 우회(개발용): `sessionStorage.setItem('treasury_user', JSON.stringify({ sb_id:'dev-master', email:'dev@local', code:'DEV', label:'개발마스터', role:'master', company:'메디아나', companies:[], menus:null, can_delete:true, can_approve:true, allowed_categories:null, action_permissions:null, must_change_password:false }))`

### 5.2 요구 설계 — 어댑터 심(seam)을 남길 것
연동 코드를 삭제하지 말고, **입력 소스를 교체 가능한 형태**로 감싼다.

```ts
// src/lib/fxRegimeInputs.ts (신규 권장)

/** 국면 판정·시뮬레이션에 필요한 자금 컨텍스트 */
export interface FxTreasuryInputs {
  totalFundKRW:   number       // 가용 자금 총액
  fxHoldingFx:    number       // 현재 외화 보유 (외화 단위)
  monthlyInflowFx: number      // 월 외화 유입액 (외화 단위) — §6 재설계에 필수
  fxPayableFx:    number       // 향후 3개월 결제 예정액 (외화 단위)
  policyMinRatio: number | null
  policyMaxRatio: number | null
}

export type InputSource = 'manual' | 'treasury'

/**
 * 'manual'  : 화면 입력값 사용 (현재 기본값)
 * 'treasury': usePolicyDashboard / usePolicyParams 연동 (추후 활성화)
 *             ← 이 분기를 비워두되 함수 시그니처는 유지할 것
 */
export function useFxTreasuryInputs(source: InputSource): FxTreasuryInputs { /* ... */ }
```

- 화면에 **입력 패널**을 두고 값은 `localStorage`(키 예: `fx_regime_inputs_{company}`)에 보존한다.
  `policy_params` 에 저장하면 Treasury 정책값과 섞여 혼동을 부른다.
- 상단에 `수동 입력 / Treasury 연동(준비 중)` 토글을 두되, 후자는 **비활성 상태로 자리만** 둔다.
- ⚠ 연동을 되살릴 때 참고: 자금 수치는 `usePolicyDashboard` 의 `totalFundAvail` / `fxTotalHoldings` 가 SSOT 다.
  다른 공식을 쓰면 FX 정책 탭과 숫자가 어긋난다(세션19차에 실제로 발생한 사고).

### 6.1 왜 재설계해야 하나
현재 백테스트는 **"고정 자금 풀을 목표 비중으로 리밸런싱"** 모델이라, 비중이 목표에 미달하면
외화를 **매수**한다. 그런데 실측 결과 **메디아나는 외화 순수입(수출) 구조**다.

| 근거 (메디아나, 2026-04-14 ~ 08-07) | 값 |
|---|---:|
| 운전자금 USD 잔고 | 6,810,645 → 9,230,660 (**+2.42M**) |
| 운용 외화 정기예금 | 1M → 6M (**+5.0M**) |
| 같은 기간 USD 매도 완료 | **4.0M** |
| `fx_trade_history` 방향 | **12건 전부 sell · 매수 0건** |

4M 을 팔고도 보유가 7.4M 늘었다 → 기간 유입 ≈ 11.4M, **월 약 3.0M USD**.

> **범위 주의**: 이 순수입 구조는 **메디아나에만 해당한다.**
> 셀바스에이아이·셀바스헬스케어는 확인되지 않았으므로 일반화하지 말 것.
> 재설계 시 유입액을 **법인별 수동 입력**으로 받으면 이 문제가 자연히 해소된다.

그 결과 기존 백테스트는 실제로는 하지 않을 매수를 다수 생성했고,
"밴드 무시 시 −2.3억 / 69회 거래" 같은 **왜곡된 성과**가 나왔다. → **이 수치는 폐기.**

### 6.2 재설계 스펙
```
[모델]
  매기(월 또는 주) 외화가 외생적으로 유입된다.        ← monthlyInflowFx (수동 입력)
  의사결정 = 매수/매도가 아니라
             "이번에 들어온(그리고 쌓여 있는) 외화를 지금 환전할지 / 미룰지 / 얼마나 할지"
  국면 신호 해석:
     ①②(상승) → 환전 지연(Lagging), 보유 유지
     ③(횡보)   → 정책 기준선대로 정기 환전
     ④⑤(하락) → 즉시·대량 환전(Leading)
  제약: 결제 버퍼(fxPayableFx)만큼은 항상 남긴다.
        정책 밴드가 있으면 보유 비중 상·하한으로 클램프한다.

[벤치마크 — 반드시 2개 모두]
  ① 즉시 전액 환전  : 유입 즉시 100% 환전 (가장 보수적)
  ② 전혀 환전 안 함 : 계속 누적 (환율 노출 최대)
  ※ 기존의 "고정 비중 유지"는 순수입 구조에서 성립하지 않으므로 제거

[성과 지표]
  - 총 환전 실현액(원화) — 이게 핵심. 같은 외화를 얼마나 비싸게 팔았나
  - 가중평균 실현환율 vs 기간 평균환율   ← 가장 직관적인 성과 지표
  - 미환전 잔량 및 기말 평가액
  - 거래 횟수·비용
  - 최대 미환전 노출액(리스크)
```

**핵심 질문을 바꿔야 한다**: "포트폴리오 수익률이 얼마인가"가 아니라
**"같은 외화를 평균 환율보다 비싸게 팔았는가"** 이다. 후자가 자금팀의 실제 KPI다.

### 6.3 재설계 시 유지할 것
- `fxRegime.ts` 는 **그대로 재사용**한다. 판정 로직은 손대지 않는다.
- `runBacktest()` 의 시그니처만 바꾸고 내부 모델을 교체한다.
- `BacktestTab.tsx` 상단의 ⛔ 적색 경고 배너는 **재설계 완료 후 제거**한다.

### 8.1 확정된 설계 판단 (뒤집지 말 것 — 근거는 §4.3)
1. ADX·ATR → Efficiency Ratio·변동성 Z-Score 대체 (ECOS 종가만 제공)
2. 칼만은 JS 구현 (1차원이라 20줄, Python 불필요)
3. 평활가/원시가 용도 분리
4. 칼만 `q=2, r=10`
5. `minTrendMovePct = 1.5%`
6. 히스테리시스 `confirmDays = 2`

### 8.2 이번 세션에서 잡은 버그 (회귀 주의)
| 버그 | 증상 |
|---|---|
| `fetchEcosRates_` 가 날짜를 버림 | 시계열 저장 불가 |
| 평활가로 변동성 계산 | 연환산 변동성 1.11%(실제 5.72%) → 고/저변동성 축 무력화 |
