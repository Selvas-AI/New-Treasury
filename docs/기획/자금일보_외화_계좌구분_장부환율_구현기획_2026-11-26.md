# 자금일보 외화 항목 — 계좌구분·장부환율 반영 구현기획 (2026-11-26)

> 상태: **Q1~Q3 = A 확정(2026-11-26) · 1단계 구현 완료 / SQL 실행 대기** (`docs/db/fx_report_item_account.sql`) · 2·3단계 미착수
> 선행: `fx_report_item_ledger.sql`(2026-11-25, 실행 완료) — 자금일보 외화 항목 → 원장 항목 단위 반영

## 1. 요청 요약 (실무 담당자)

- 지금은 장부환율이 **잔액 기준 선입선출(FIFO)** 로 반영되는데, 외화예금을 **계좌유형별로** 나눠 관리하고 싶다.
- 자금일보 외화 입력창에 **'장부환율'·'계좌구분'** 항목을 추가해 달라.
  - 계좌구분: 보통예금 / MMDA
  - 장부환율: 외화 계좌별 장부환율 입력·반영
- 계좌구분·장부환율이 **각각 구분되어 자금일보에 반영**되기를 원한다.

## 2. 현행 구조 진단

| 구성 | 현재 | 계좌유형 지원 |
|---|---|---|
| 원장 로트(`fx_lots.account_type`) | demand_deposit / mmda / term_deposit | ✅ 이미 있음 |
| 계좌 대체(`transfer_fx_lots`, 외화거래명세 › 계좌 대체) | 보통예금↔MMDA↔정기예금 이동 기록 | ✅ |
| 출금 소진 RPC(`consume_fx_lots_for_source`) | `p_account_type` 지정 시 **그 계좌에서만** 소진 | ✅ 이미 있음 |
| **자금일보 항목 → 원장**(`sync_report_item_ledger`) | 입금 = 항상 **보통예금** 로트 · 출금 = `p_account_type => null`(우선순위 FIFO, 계좌 섞임) | ❌ **여기가 빈 곳** |
| 자금일보 항목 입력(ItemsSection) | 외화 항목에 '환율' 1칸 | ❌ 계좌구분 없음 |
| 자금일보 잔액(`daily.fx_usd` 등) | **통화별 1개**(계좌 구분 없음) | ❌ |
| 미반영 대사(`lib/fxReconcile`) | 운전 계좌(보통예금+MMDA) 합계로 비교 | 영향 없음(합계 기준) |

→ **원장은 이미 계좌별 FIFO를 할 수 있다.** 자금일보 항목이 계좌를 넘겨주지 않는 것이 문제다.
  요청의 핵심(계좌별 장부환율 관리)은 **항목에 계좌구분 1칸 + RPC 두 줄 수정**으로 대부분 해결된다.

## 3. 결정 필요 항목

### Q1. 출금 항목의 '장부환율'은 무엇인가 ★ 가장 중요

입금과 출금에서 환율의 의미가 다르다.

| | 입금 | 출금 |
|---|---|---|
| 의미 | 새로 들어온 외화의 **취득(장부)환율** | 나가는 외화의 장부환율은 **이미 원장에 있다**(그 계좌의 FIFO 로트) |
| 입력값의 쓰임 | 로트의 `acq_rate` | 지금은 **처분(적용)환율** — 원화 환산·환차손익 계산 |

- **(A) 권장** — 출금은 장부환율을 **입력받지 않고 자동 표시**한다.
  선택한 계좌의 FIFO 로트로 "이 출금의 장부환율 ≈ X원(가중평균)"을 미리 보여 주고, 입력칸은 **'적용환율'**(결제일 환율)로 이름을 분리한다.
  환차손익 = 금액 × (적용환율 − FIFO 장부환율).
- **(B)** — 출금도 장부환율을 직접 입력한다. 원장이 어느 로트를 뺄지 정할 수 없게 되어 FIFO 구조와 충돌하고, 원장 장부환율과 입력값이 갈라진다. **비권장.**

### Q2. 자금일보 **잔액**도 계좌별로 나눌 것인가

- **(A) 권장** — 잔액 입력은 현행(통화별 1개)을 유지한다. 계좌별 잔액·장부환율은 **원장에서 읽어** 자금일보 요약표 외화 행에 보조 행으로 보여 준다.
  예: `USD 1,234,567 (원장: 보통예금 1,000,000 @1,380.2 · MMDA 234,567 @1,365.0)`
- **(B)** — `daily` 테이블에 `fx_usd_mmda` 같은 컬럼을 추가해 계좌별 잔액을 입력받는다. 은행 잔고 입력 부담이 늘고 CMS 대사·대시보드·정책 분모 등 **연쇄 수정 범위가 크다**. 꼭 필요하면 2단계로 분리한다.

### Q3. 이미 반영된 기존 항목(계좌 미지정)

- **(A) 권장** — 그대로 둔다. 화면에 '자동(우선순위)'으로 표시하고, 신규 입력부터 계좌구분을 **필수**로 받는다. 필요한 건만 사용자가 항목을 열어 계좌를 지정하면 재동기화된다.
- **(B)** — 일괄로 보통예금으로 지정한다. 과거 출금이 MMDA 로트를 소진했던 경우 재동기화 때 결과가 바뀌므로 **비권장**.

## 4. 구현 범위 (권장안 A/A/A 기준)

### 1단계 — 항목 계좌구분 + 원장 반영 (핵심)

**DB** `docs/db/fx_report_item_account.sql` (신규, 1회 실행·재실행 안전)
- `daily_report_items.fx_account_type text null check (fx_account_type in ('demand_deposit','mmda'))`
- `sync_report_item_ledger` 수정:
  - 입금: `account_type => coalesce(v_item.fx_account_type, 'demand_deposit')`
  - 출금: `p_account_type => v_item.fx_account_type` (null = 기존과 같은 우선순위 FIFO)
  - 그 계좌 잔액 부족 → 기존 예외 그대로(메시지에 계좌명 포함, 이미 구현됨)
- 결과표: 컬럼·RPC 확인

**화면** `src/components/daily-report/ItemsSection.tsx`
- 외화·원장 반영 대상 항목에 **계좌구분** 선택(보통예금 / MMDA), 신규는 필수(기본값 없음 → 선택 전 저장 시 안내)
- 환율 칸 이름: 입금 = **장부환율(취득)**, 출금 = **적용환율**
- 출금 입력 중: 선택 계좌의 **FIFO 장부환율 미리보기**와 예상 환차손익 표시
  (`previewFifoConsumption`을 계좌유형으로 필터한 로트에 적용 — 서버와 같은 규칙)
- 반영 배지: `💱 원장 반영 · MMDA @1,365.0`
- 계좌구분을 바꾸면 재동기화(`updateItemWithLedger`의 재반영 조건에 `fx_account_type` 추가)

**규칙 공유** `src/lib/fxReportItemLedger.ts`
- `REPORT_ITEM_ACCOUNT_TYPES = ['demand_deposit','mmda']`, 라벨, "출금 계좌 잔액 부족" 사전 경고 함수
- ⚠ 서버 RPC와 규칙이 같아야 한다(파일 머리 주석 유지)

**훅** `useDailyReportItems` — `fx_account_type` 매핑(컬럼 없을 때 폴백, `fx_rate`와 같은 방식)

### 2단계 — 자금일보에 계좌별 장부환율 표시

`ReportSummaryTable` 외화 행 아래 보조 행(접기 가능):
- 원장 기준 계좌별 **잔액 · 가중평균 장부환율**(보고대상일 시점에 이용 가능한 로트, `isLotAvailable`)
- 운전 계좌 합계가 자금일보 잔액과 다르면 기존 '미반영 증감' 안내로 연결
- 데이터: `useFxLots`(통화별) — 새 계산 없음, `weightedBookRate`를 계좌별로 적용

### 3단계 (선택) — 외화거래명세 보완
- 원장 탭 report_item 행에 계좌 표시(계좌 필터는 이미 있음)

## 6. 위험·운영 전제

1. **계좌 대체가 원장에 기록돼 있어야 한다.** 은행에서 보통예금→MMDA로 옮기고 외화거래명세 › 계좌 대체를 기록하지 않으면, 원장에 MMDA 로트가 없어 **MMDA 출금 반영이 '잔액 부족'으로 실패**한다.
   → 실패 배지에 "계좌 대체 기록 필요" 안내를 넣는다. 필요하면 자금일보에 '계좌 대체' 항목 유형을 두는 것을 후속 검토한다(같은 외화의 계좌 간 이동이라 손익 없음).
2. 출금을 다른 계좌로 고치면 그 계좌 잔액으로 다시 소진한다 — 잔액이 부족하면 수정 자체가 거부된다(아무것도 바뀌지 않음).
3. 장부환율 자동 표시(Q1-A)는 **미리보기**다. 저장 시점에 다른 출금이 먼저 반영되면 실제 소진 로트가 달라질 수 있다(서버 결과가 정본).
