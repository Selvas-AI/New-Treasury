## 1. ⭐⭐ 용어 사전 — 오해하면 안 되는 것들

**이 절이 이 문서의 핵심이다.** 같은 대상을 가리키는 말이 여러 개이거나,
비슷한 말이 다른 것을 가리키는 경우가 있어 혼동이 발생했다.

### 1.1 세 개의 축 (가장 중요)

| 용어 | 정확한 의미 | 흔한 오해 |
|---|---|---|
| **추세 (Trend)** | 환율이 **어느 방향**으로 가는가. 5단계(①강한상승 ②온건상승 ③횡보 ④온건하락 ⑤강한하락) | "추세가 좋다/나쁘다"가 아님. **방향과 곧기**만 잰다 |
| **변동성 (Volatility)** | 가는 동안 **얼마나 흔들리는가**. 2단계(A 고변동 / B 저변동) | 추세와 무관. "많이 내렸다"와 "많이 흔들렸다"는 **다른 것** |
| **수준 (Level)** ⭐ | 지금 환율이 **비싼가 싼가**. 5등급(VH/H/N/L/VL) | **추세와 완전히 독립.** 높은 데서 내릴 수도, 낮은 데서 내릴 수도 있음 |

> **국면(Regime)** = 추세 × 변동성. 예: `5-B` = 강한하락 / 저변동성.
> **수준은 국면에 포함되지 않는다.** 별도 축이다. 이 구분이 시스템 전체의 뼈대다.

### 1.2 앵커 관련

| 용어 | 의미 |
|---|---|
| **앵커 (anchor)** | 수준 판단의 **기준 환율**. "이 값보다 높으면 비싸다"의 그 값 |
| **횡보 구간 / 박스권** | 앵커 후보를 찾는 방법. 최근 3년 중 **폭이 좁고 제자리로 돌아온** 60영업일 구간 |
| **편차 (dev)** | `(현재환율 − 앵커) / 앵커`. 이 값으로 VH~VL 등급이 결정됨 |
| **앵커 노후화** | 앵커를 오래 안 바꾸면 "현재는 영원히 고가"가 되어 변별력 상실. 분기 재검토 필요 |

⚠ **앵커는 자동으로 바뀌지 않는다.** 담당자가 골라 `policy_params`에 고정한다.
매일 재계산하면 기준이 흔들려 불필요한 매매가 발생하기 때문이다.

### 1.3 ⭐ 정책 프로토콜 탭 — 사용자가 가장 혼란스러워한 부분

이 탭에 **세 종류의 설정**이 섞여 있는데 이름이 그 차이를 드러내지 못한다.

#### ① 「목표 외화 보유 비율 — 수준 × 추세」 (5×3 표)
- **정체**: 이 시스템의 **정책 그 자체**. 실제로 쓰이는 값
- **의미**: 각 칸의 숫자 = **목표 외화 보유 비중**. **낮을수록 많이 환전**하라는 뜻
- ⚠ **파는 비율이 아니다.** "15%"는 "15% 팔아라"가 아니라 **"15%만 남겨라"** = 대부분 팔아라
- 실제 환전액 = `(현재 비중 − 목표 비중) × 가용자금 총액`
- 현재 범위 15%~42% (근거: `fxRegime.ts` DEFAULT_LEVEL_TARGETS 주석의 실측표)

#### ② 「(구) 국면 단독 목표 비율」 (접힌 10행 표) ← **왜 있는지 질문받음**
- **정체**: **수준 축 도입 이전의 낡은 로직.** 평소엔 쓰이지 않음
- **왜 안 지웠나**: ④ 규칙 검증 탭에서 **"수준 축이 정말 나은가"를 비교하는 대조군**으로 필요
  - 이게 없으면 "구 로직은 1,449원에 팔았고 수준 축은 1,528원에 팔았다"는 증명이 불가능
  - 2026-07 사고 재현 검증의 근거이므로 **삭제 금지**
- **언제 쓰이나**: `useLevelAxis=false`(앵커 미설정 또는 수동 OFF)일 때만
- **개선 제안**: 이름을 「대조군: 수준 축 도입 전 로직」 정도로 바꾸고,
  "평상시 사용되지 않음 · 검증 비교용" 배지를 달아 혼동을 없앨 것

#### ③ 「판정 파라미터」 (8+5개 숫자 필드) ← **이름이 모호하다는 지적받음**
- **정체**: 국면·수준을 **어떻게 판정할지** 정하는 계산 상수들
- **실제로는 성격이 다른 3그룹이 섞여 있다.** 분리 제안:

| 그룹 | 항목 | 무엇을 정하나 |
|---|---|---|
| **추세 판정** | 강한추세 기준(ER), 추세인정 기준(ER), 최소 순변동폭, 국면 확정 일수 | "이걸 추세라고 부를까?" |
| **수준 판정** | 매우높음/높음/낮음/매우낮음 기준(%) | "이걸 비싸다고 부를까?" |
| **집행 규칙** | 리밸런싱 밴드, 강제 환전 기한, 칼만 Q/R | "언제 실제로 거래할까?" |

> **A과제 권장 방향**: 이 3그룹을 소제목으로 나누고, 각 그룹 앞에 한 줄 설명을 붙일 것.
> 지금은 13개 숫자가 한 덩어리로 나열돼 있어 무엇을 만지면 무엇이 바뀌는지 알 수 없다.

### 1.4 지표 (Indicators)

| 화면 표기 | 실제 의미 | 주의 |
|---|---|---|
| **추세강도 (ER)** | Kaufman Efficiency Ratio. `순이동 ÷ 총이동 × 100`. 100=곧게, 0=왕복 | ADX가 아니다. ECOS가 고가/저가를 안 줘서 대체함 |
| **20일 순변동** | 최근 20영업일 실제 변동률 | ER의 **크기 게이트**. ER은 스케일 불변이라 0.1원 움직여도 100이 나옴 |
| **MACD 히스토그램** | 추세 가속도 | 방향이 아니라 "힘이 붙는가" |
| **연환산 변동성** | 최근 20일 등락을 1년 기준 환산 | ⚠ **원시 종가**로 계산. 평활가로 재면 과소평가됨 |
| **변동성 Z-Score** | 지금 변동성이 1년 분포에서 어디쯤 | ATR 대체. ≥1.0이면 고변동(A) |
| **볼린저 %B** | 밴드 내 상대 위치. 0=하단, 1=상단 | — |
| **칼만 평활** | 잔떨림 제거한 흐름선 | 추세 지표에만 사용. 변동성엔 쓰지 말 것 |

### 1.5 탭 구조 (의사결정 흐름 순)

```
① 📊 현재 국면    진단 — 무슨 일이 벌어지고 있나        (매일)
② 💰 환전 판단    집행 — 이번에 얼마를 팔 것인가        (권고 발생 시)
③ 🎯 정책 프로토콜 기준 — 우리 규칙은 무엇인가          (분기)
④ ⚖️ 규칙 검증    검증 — 그 규칙이 옳은가              (정책 변경 시)
```

⚠ **④는 "시뮬레이션"이 아니다.** 과거 실적 재현이 아니라,
**오늘 입력값을 과거에 놓고 두 규칙을 겨루게 한 실험**이다.
금액은 참고치이고, **실현환율이 기간평균보다 높은가 / 두 규칙의 차이**만 유효하다.
(이 오해로 사용자가 혼란스러워했으므로 이름을 「규칙 검증」으로 바꿨다)

### 1.6 손익 용어 (②탭)

| 용어 | 의미 | ⚠ 핵심 |
|---|---|---|
| **평가손익** | 팔지 않아도 결산 시 P/L에 잡히는 손익 | 화폐성 외화항목이라 **매 결산기 마감환율로 평가됨** |
| **실현손익** | 실제로 팔았을 때 확정되는 손익 | 평가손익의 일부가 계정만 바뀌어 넘어가는 것 |
| **손익분기(BEP)** | 평균취득환율. 여기까지 올라야 평가손실 소멸 | — |
| **분기 손실 한도** | 한 분기에 실현할 손실의 상한 | ⚠ 손실을 **줄이는** 게 아니라 **인식 시점을 분산**. 총액은 동일 |

> ⭐ **이 시스템이 깨려는 착시**: "평단 아래라 팔면 손실 확정되니 안 판다"
> → 팔든 안 팔든 손실은 **이미 P/L에 있다.** 계정 이름만 외환차손 ↔ 외화환산손실로 바뀔 뿐.
> 안 파는 것은 손실을 미루는 게 아니라 **같은 손실 + 추가 환율 위험**을 떠안는 선택이다.
> (세무 취급은 회계팀·감사인 확인 필요 — 시스템이 판단하지 않음)

### 2.4 FIFO 손익 경로 시뮬레이션 (2026-08-12 추가)
- 규칙 검증 엔진은 시작 외화 재고를 입력 장부환율의 **개시 FIFO 로트**로 두고,
  이후 매일 유입되는 외화는 그날 시장환율로 별도 로트를 만든다.
- 환전 권고량은 기존 `evaluateRegime(series.slice(0, i+1), ...)` 결과를 그대로 쓰고,
  손익 계산 단계에서만 가장 오래된 로트부터 소진한다.
- 화면에 시장환율/FIFO 잔존 장부환율과 누적 실현손익/남은 평가손익/총손익 경로를 분리 표시한다.
- 고원가 개시 로트가 먼저 소진되면 잔존 장부환율과 평가손실이 정상화될 수 있으나,
  **0 수렴 또는 미래 이익을 보장하지 않는다.** 미래 유입환율·시장경로·환전 속도에 달린 조건부 결과다.
- 6/12/24/36개월과 현재 유지/상승/하락/최근 1년 등락 반복 가정을 선택할 수 있다.
  고원가 개시 로트 소진일, 장부환율이 시장가 ±1%에 들어오는 날, 총손익 0 이상 도달일을 표시한다.

- 사용자의 재확인 버튼으로만 저장하며, import-key/거래 5개 필드 조합으로 중복을 건너뛴다.
- 재고 CSV는 0원 2건을 제외하고 실제 취득일·장부환율을 보존한 개시 로트로 등록한다.
- 매각 CSV는 개시 이전 완료 실적으로 `fx_trade_history`에 등록하되 현재 개시 로트를 소진하지 않는다.
- 규칙 검증 화면은 등록된 실제 매각의 가중평균환율·확정손익과 알고리즘 실험을 나란히 표시한다.
- `docs/db/fx_fifo_trade_rpc.sql`: 개시 이후 환전 완료와 FIFO 소진, 완료 취소와 원복을 각각 단일 트랜잭션으로 처리한다.
  `authenticated`이며 master/admin/can_approve 사용자만 실행 가능하고 anon 권한은 명시적으로 회수한다.
- CSV 선택 컨트롤은 브라우저 기본 버튼 대신 명시적 버튼이 숨김 file input을 여는 방식이다.
- 개시 로트는 소진 이력이 없을 때만 수정/삭제 가능하다. 과거 CSV 매각 실적도 수정/삭제할 수 있으며,
  개시 이후 원장 연동 거래는 원복 RPC를 사용해야 하므로 이 화면의 단순 삭제 대상에서 제외한다.

## 3. ⭐ A과제 — 정책 프로토콜 탭 정리 (최우선)

> ✅ 2026-08-12 완료: 활성 로직 표시, 실제 정책/대조군 명칭 분리, 13개 설정의 3그룹화,
> 목표 잔존 비중 설명, 저장 전 오늘 결론 미리보기를 적용했다. 미리보기는 DB 저장 없이
> 초안 프로토콜을 기존 `evaluateRegime()`에 전달해 계산한다.
> 후속 개선: 화면의 `기본` 표기를 `권장안`으로 변경했다. 정책 매트릭스에는 15~42% 권장 폭의
> 실측 근거와 폭을 넓히거나 좁힐 때의 노출·실현환율 trade-off를 표시하고, 13개 설정 카드에는
> 의미·권장 이유·상향/하향 시 장단점을 쉬운 문장으로 설명하는 도움말을 추가했다.
> 입력 개선: 15개 정책 셀을 직접 입력하는 대신 `최소 잔존 비중 / 중립 잔존 비중 / 최대 잔존 비중`
> 세 게이지로 자동 조정할 수 있다. 권장안 셀의 최소~중립~최대 사이 상대 위치는 고정하며,
> 조정 즉시 권장안 대비 환전 강도·상승 기회·하락 노출의 장단점을 문장으로 안내한다.

### 3.1 현재 문제
1. 「판정 파라미터」 13개가 **한 덩어리**로 나열 — 성격이 다른 3그룹인데 구분 없음
2. 「(구) 국면 단독 목표 비율」이 **왜 있는지** 화면상 설명 부족
3. 어떤 값이 **지금 실제로 쓰이는지** 알 수 없음 (수준 축 ON/OFF에 따라 달라짐)
4. 값을 바꿨을 때 **무엇이 어떻게 변하는지** 즉시 보이지 않음

### 3.2 권장 방향
- **§1.3의 3그룹으로 소제목 분리** + 각 그룹 한 줄 설명
- 현재 활성 로직을 상단에 **명시**: 「지금 적용 중: 수준 × 추세 매트릭스」
- (구) 표는 **「대조군 (검증 비교용 · 평상시 미사용)」** 으로 개명 + 배지
- 값 변경 시 **"이 값을 바꾸면 오늘 결론이 이렇게 바뀝니다"** 미리보기 (선택)
- 저장 전후 **결론 카드 변화**를 보여주면 가장 직관적

## 5. D과제 — FIFO 외화 입출금 장부 (기획부터)

### 5.1 왜 필요한가
회사는 **FIFO로 외화 처분**한다. 지금 시스템은 평균취득환율을 **수동 입력**받아
근사할 뿐이라, 실제 환차손익과 어긋난다.

FIFO에서는 **지금 팔면 가장 비싼 옛 물량부터 나가므로** 손실이 앞쪽에 집중된다.
이 효과는 가중평균 근사로는 재현되지 않는다.

### 5.2 이미 있는 선행 기획
`docs/기획/외화원장_FIFO_가중평균.md` — 세션21에 작성한 기획서.
`fx_lots` / `fx_lot_consumptions` 테이블 설계, 원타임 입력 플로우 등이 담겨 있다.
**이걸 먼저 읽고 이어서 확장할 것.**

### 5.3 설계 시 유의점
- **한 번 입력하면 여러 장부에 반영**되어야 한다 (사용자 요구). 기존 연동 팝업 패턴 재사용
- 외화 입금 시점의 환율이 곧 취득원가 → 자금일보 입금 항목과 연결 가능
- ⚠ FX 손익을 **자금일보 현금 라인으로 넣지 말 것** — 이중계상 되어 검증식이 깨진다
  (선행 기획서에 이유 상세히 적혀 있음)
- 개시 시점(cutover) 필요: 과거 취득 이력이 없으므로 **개시 로트**를 수동 입력으로 시작

## 7. ⚠️ 반드시 지킬 규칙 (어기면 같은 함정 재발)

### 7.1 ⛔ 프로덕션 DB 직접 조작 금지
Supabase에 **DELETE/UPDATE/INSERT 직접 실행 금지.** 조회만 허용.
2026-06-25에 데이터 106건 소실 사고 있었음. 변경이 필요하면 **UI 버튼을 만들어 사용자가 클릭**하게 할 것.

### 7.2 엔진 설계 규칙
1. **평활가 vs 원시가 분리** — 추세 지표는 칼만 평활, 변동성·볼린저는 **원시 종가**
2. **`minTrendMovePct` 크기 게이트 제거 금지** — ER은 스케일 불변이라 0.1원에도 100이 나옴
3. **백테스트는 `evaluateRegime()`를 그대로 호출** — 별도 판정 로직 만들면 실전과 어긋남
4. **look-ahead 금지** — 항상 `series.slice(0, i+1)`
5. **`volZScore`는 누적합 구현 유지** — 슬라이스는 O(n²)라 브라우저 멈춤
6. **(구) 국면 매핑 삭제 금지** — ④탭 대조군

### 7.3 데이터·API 제약 (실측)
| 제약 | 대응 |
|---|---|
| PostgREST `max-rows=1000` (조용히 잘림) | keyset 페이지네이션 |
| ECOS 1회 500건 상한 | 연 단위로 끊어 호출 |
| GAS 연속 호출 간헐 실패 | 3회 재시도 + 5초 간격, 부분 성공 허용 |
| ECOS는 종가만 제공 | ADX·ATR 사용 불가 → ER·볼Z로 대체 |
| GAS 일일 할당량 | **폴링 금지**, `isGasBlocked()` 준수 |

### 7.4 React 함정
- 훅 반환 객체·콜백은 **반드시 메모이즈** (무한 렌더 루프 전례)
- **JSX 헬퍼를 렌더 함수 안에 정의 금지** (포커스 유실)
- `<Routes>` 조건부는 **라우트마다 개별로**
- 팝업 애니메이션: `@keyframes`에 `translate` 넣지 말 것 (Tailwind와 충돌해 깜빡임)
